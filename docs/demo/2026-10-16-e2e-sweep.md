# E2E sweep — 2026-10-16

I tested the app end to end three ways: the Playwright suite, a scripted live-AI Playwright walk through every page (local, demo user), and Claude in Chrome against prod (`placed-lovat.vercel.app`, demo user Ayşe), plus a 390px mobile pass on prod.

## Fixed (branch `fix/e2e-sweep`)

| # | Where | Problem | Fix |
|---|---|---|---|
| 1 | CV Score | Scoring a CV for a new sector took **80–120 s** on prod, because one smart-tier call judged ~46 rules (the UI promises "up to a minute"). | `judgeCvRules` judges rule batches of ≤12 in parallel, with a 120 s deadline per batch. Gemini, same CV and sector: **108 s → 32 s**. If a batch fails, its rules are marked not counted, the score is labelled "AI review unavailable", and it is never cached. |
| 2 | Job page | A correct "Strong" match was shown as "Partial" with no evidence. The model quotes the CV line with the list marker our prompt renders it with (`"  - Used Python and SQL…"`), and verification rejected that prefix. | `stripListMarker` runs before verifying a quote, in both explainMatch and the CV judge. `EXPLAIN_CACHE_VERSION` is bumped to 3, so the affected cached rows are recomputed. |
| 3 | Job page | The same requirement appeared twice ("Knowledge in SQL and Python…"), because tagJob emits one row per skill. | `mergeSameText` merges rows with the same text: Strong only if every part is Strong, Missing only if every part is Missing, otherwise Partial. It also runs on cached rows when they're read. |
| 4 | Job page | The grey summary box repeated the first paragraph of the description, cut off mid-word. | The summary is hidden when it is just the opening of the posting. |
| 5 | Header | "Feed" was highlighted on every page. | New client `NavLinks` component with `usePathname`. The active link gets `aria-current="page"`. |
| 6 | Header | The XP label wrapped ("…to level / 3"). | Made the label wider and set it to `nowrap`. |
| 7 | Mobile header | At 390px the header took ~180 px (nav wrapped into two rows plus a stats row). | The nav is one horizontally scrollable row on phones, and the header is now 99 px. |
| 8 | Tracker, mobile | Inbox email subjects were squeezed into a narrow column next to the buttons. | The subject takes its own line on phones. |
| 9 | Feed card | Cards showed "0/0 must-haves". | Now "No must-haves listed · 2/2 nice-to-haves". |
| 10 | LinkedIn | The profile link was wiped whenever scoring returned an error, e.g. a name mismatch. | The input is now controlled, so the link stays after an error. |
| 11 | Target role | Readiness showed 9% for Consulting. With 5 live roles, every skill came from a single posting, so the % was noise. | The % counts only skills that ≥2 live roles ask for. If no skill qualifies, it says "No skill shows up in more than one live X role yet". The list itself is unchanged. |
| 12 | e2e suite | 5 stale tests: the "Next" selector matched the Next.js dev-tools button, the auth-callback test predated `?error=link`, the upload test was still marked `test.fail` although the bug had been fixed, and the demo spec had stale selectors for the collapsed "More fixes" list. | Tests updated. Now 33 passed, 1 skipped. |

## Checked and fine

- Landing, login, the demo sign-in, onboarding, and the redirects for logged-out users.
- Upload → profile, the sector switch, quiz, and the "Myth vs evidence" section.
- Feed filters, save and mark-applied, job page, tailoring (the diff, accept/edit/keep, "From your original CV"), and the Applied → badge flow.
- Tracker plus the Inbox Agent demo sync: an email from Celonis automatically moved the card to Applied, and an Undo is offered.
- Autopilot setup on prod (15/15 answers, unlocked) and the Settings delete confirmation.
- No horizontal overflow at 390px on any page tested.

## Not fixed: needs a decision or is out of scope

- **Thin requirement extraction**: the Celonis JD lists about 9 qualifications, but tagJob stored only SQL and Python, both as nice-to-haves, so the card says "No must-haves stated". This is a tagger prompt/re-ingest issue and is costly to re-run before the deadline.
- **Tailoring wording**: "Used Python and SQL to collect and clean" was rewritten as "Cleaned and analysed…", adding the verb "analysed". It is minor, but the truth gate does not catch new verbs.
- **Only 5 live Consulting roles** (MBB and Big 4 gaps from the ingest-coverage note), which is why Target role is thin for Consulting.
- **Anthropic provider is slow**: locally (`AI_PROVIDER=anthropic`, Sonnet) the batched judge still takes ~80 s. Prod runs Gemini.
- **Landing page** is a single hero with no product preview. Worth a design pass before judging.
