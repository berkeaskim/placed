# Placed for Mac — Electron desktop app

Spec: this file's "Spec" section is the binding authority for every task below.

## Spec

Placed today is a local-first Next.js 16 app (SQLite via better-sqlite3, no login) that a student runs with `npm run dev`
and opens at `http://127.0.0.1:3000`. We ship the same app as a double-clickable macOS application so a student who has
never used a terminal can install it from a DMG.

Decisions already made with Berke (do not revisit):

| Topic | Decision |
|---|---|
| Shell | Electron. The Next.js server runs inside the app (Next `output: "standalone"` bundle), spawned from the Electron main process with `utilityProcess.fork` (so Electron's bundled Node runs it, no separate Node download). |
| Signing | Unsigned (ad-hoc signature only). No Apple Developer ID, no notarization. README explains right-click → Open / "Open Anyway". |
| Data | `~/Library/Application Support/Placed/data` (`PLACED_DATA_DIR`). First launch with no data offers a one-time import of an existing Placed `data` folder (copy, never move). Web/dev mode keeps using `./data`. |
| Port | Fixed `127.0.0.1:3917` in desktop mode (`PLACED_DESKTOP_PORT`). Dev stays on 3000. The Chrome extension accepts both. |
| App type | Classic Dock app: closing the last window quits the app (and the server). |
| Background refresh | The existing in-server scheduler (instrumentation.ts) runs while the app is open. Settings gets an "Open Placed at login" toggle (Electron login item). The LaunchAgent (`npm run schedule:install`) stays as-is for repo users; the desktop Settings copy must not tell app users to run npm. |
| Updates | GitHub Actions builds the DMG on `v*` tags and attaches it to the GitHub release. The app checks `https://api.github.com/repos/berkeaskim/placed/releases/latest` and shows a "new version available" dialog linking to the release page. No silent auto-update (unsigned). |
| Arch | Apple Silicon (arm64) only for now. |

Global constraints (bind every task):

- The server listens on `127.0.0.1` only. Loopback is the security boundary (no auth). Never bind `0.0.0.0`.
- Never read or write the main checkout's `./data`, the user's real `~/Library/Application Support/Placed`, or any
  `.env.local`. Tests use temp dirs (`tests/setup/temp-data-dir.ts` for vitest; `PLACED_USER_DATA_DIR` for the app).
- Never run the app with `AI_MODE=fixture` outside vitest/Playwright. With no AI configured the app shows its
  "AI off" banner; that is the expected state in a fresh desktop test.
- Existing behaviour of `npm run dev` / `npm run build` / `npm run start` / the LaunchAgent must not change.
- `npm run typecheck`, `npm run lint`, `npm test` stay green after every task. New pure logic gets vitest tests under
  `tests/` (the root vitest config only includes `tests/**/*.test.ts`; add a glob for `desktop/src/**/*.test.ts` if a
  task puts tests next to desktop code — pick one and keep it).
- Desktop code lives in `desktop/` with its own `package.json` (electron + electron-builder as devDependencies, no
  runtime deps) so electron-builder never tries to bundle the root app's node_modules. Root `package.json` gets the
  orchestrating `desktop:*` scripts.
- Everything the server reads relative to `process.cwd()` (seed/, fixtures/, drizzle/, public/fonts) must resolve in
  the packaged app: the server child's cwd is the standalone dir, and `next.config.ts` `outputFileTracingIncludes`
  already copies those folders there. Do not introduce new cwd-relative reads.
- The desktop shell detects desktop mode via env `PLACED_DESKTOP=1` on the server; `lib/desktop.ts` exports
  `isDesktop()` and `DESKTOP_PORT = 3917` and is the only place that constant lives in app code.
- Commit after every task with a message in the repo's style (`feat(desktop): …`, `chore(desktop): …`) ending with
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Never dispatch subagents from inside a task; never push; never touch other worktrees.

Repository facts the tasks rely on:

- `lib/db/paths.ts`: `dataDir()` = `PLACED_DATA_DIR` or `<cwd>/data`; `migrationsDir()` = `PLACED_MIGRATIONS_DIR` or `<cwd>/drizzle`.
- `lib/db/client.ts`: migrations run on first use. Seeding (companies/jobs) happens ONLY in `scripts/setup.ts` today.
- `instrumentation.ts` starts `startIngestScheduler()` in the Node runtime.
- `scripts/pack-extension.mjs` runs on `predev`/`prebuild`, writes `public/placed-autopilot.zip` for origin
  `PLACED_PUBLIC_ORIGIN` or `http://localhost:$PORT`.
- `extension/config.js` hardcodes `PLACED_ORIGINS` for 3000; `manifest.json` host_permissions already cover every port
  on localhost / 127.0.0.1.
- `components/settings/job-search.tsx` tells users to run `npm run schedule:install`; `app/(app)/settings/page.tsx`
  "Your data" says data is in the `data/` folder.
- `lib/ai/config.ts` `codexBin()` already searches common install dirs because a launchd/Finder-started process has no
  shell PATH.
- Tags are `vX.Y.Z` (`git tag`), `package.json` version is the app version (1.0.0 now). CI is `.github/workflows/ci.yml`.
- Host: macOS 26 (Darwin 25), arm64, Node 24 locally (engines >= 22.12), `ollama` and `codex` CLIs installed.

## Task 1 — Shared first-run setup and desktop awareness in the app

Files: `lib/desktop.ts` (new), `lib/setup/first-run.ts` (new), `scripts/setup.ts`, `instrumentation.ts`,
`components/settings/job-search.tsx`, `app/(app)/settings/page.tsx`, tests under `tests/`.

1. `lib/desktop.ts`:
   ```ts
   export const DESKTOP_PORT = 3917;
   /** True inside the Mac app: the Electron shell sets PLACED_DESKTOP=1 on the server it spawns. */
   export const isDesktop = (env: Record<string, string | undefined> = process.env) => env.PLACED_DESKTOP === "1";
   ```
2. Move the idempotent seeding out of `scripts/setup.ts` into `lib/setup/first-run.ts`:
   `export function ensureLocalSetup(opts?: { root?: string; log?: (line: string) => void }): { companies: number; curated: number; jobsInserted: number }`.
   It does exactly what setup.ts does before `ingestLive()`: `dataDir()`, `localSecretKey()`, `ensureProfile(LOCAL_USER_ID, LOCAL_USER_EMAIL)`,
   upsert companies from `seed/companies.yml` + curated programmes (`PLACED_PROGRAMMES_FILE` or `seed/programmes.yml`),
   insert `seed/jobs.json` only when the jobs table is empty. Paths resolve against `opts.root ?? process.cwd()`.
   `scripts/setup.ts` calls it and keeps its console output and `ingestLive()` + `pragma optimize` behaviour unchanged.
3. `instrumentation.ts`: when `process.env.PLACED_AUTO_SETUP === "1"`, call `ensureLocalSetup()` (inside the same
   nodejs-runtime guard, before starting the scheduler) and log one line. Errors are logged, never thrown (the server
   must still come up so the user sees a page).
4. Settings copy in desktop mode (`isDesktop()`):
   - `job-search.tsx`: instead of the `npm run schedule:install` sentence, say: "Runs while Placed is open. Turn on
     ‘Open Placed at login’ below so it runs every morning." Keep the LaunchAgent sentence for non-desktop. Hide the
     optional-scraper line in desktop mode (the Python sidecar is a repo-only feature).
   - `settings/page.tsx` "Your data": show the real folder: `Everything is stored on this computer, in <code>{dataDir()}</code>.`
     (import `dataDir` from `@/lib/db/client`). Same for both modes.
5. Tests (vitest, temp data dir):
   - `tests/setup/first-run.test.ts`: `ensureLocalSetup()` on an empty temp data dir creates the profile, inserts > 0
     companies, inserts jobs from `seed/jobs.json` when present; calling it twice is idempotent (same counts, no throw).
   - `tests/desktop.test.ts`: `isDesktop({})` false, `isDesktop({ PLACED_DESKTOP: "1" })` true; `DESKTOP_PORT === 3917`.
6. Run `npm run typecheck && npm run lint && npm test`. Commit.

Requirements:

1. `desktop/package.json`: `"name": "placed-desktop"`, `"private": true`, `"main": "dist/main.js"`,
   `version` read at build time from the root package (a `scripts/sync-version.mjs` copies root `version` in; do not
   hand-maintain two versions), devDependencies `electron` (latest stable 4-week-old major) and `electron-builder`,
   `typescript`. Scripts: `build` (tsc → `dist/`), `start` (electron .), `dist` (electron-builder, configured in Task 4).
   Own `tsconfig.json` (module NodeNext or CommonJS as Electron needs, `strict`, `outDir dist`, `rootDir src`,
   exclude tests).
2. `desktop/src/lib/paths.ts` (pure, testable): given `{ userData, resourcesPath, isPackaged, env }` return
   `{ dataDir, logsDir, serverDir, serverEntry, staticDir }`:
   - `dataDir = env.PLACED_DATA_DIR ?? join(userData, "data")`
   - `logsDir = join(userData, "logs")`

   - unpackaged (dev): `serverDir = join(<repo root>, "desktop", "stage", "server")` (same layout Task 4 produces).
   `userData` must honour env `PLACED_USER_DATA_DIR` (call `app.setPath("userData", …)` before `ready`) so tests and
   QA can run against a scratch folder.
3. `desktop/src/lib/server.ts`: `startServer({ entry, cwd, port, env, log })` forks the Next standalone `server.js` with
   `utilityProcess.fork(entry, [], { cwd, env, stdio: "pipe" })`. Env it sets:
   `PORT=3917`, `HOSTNAME=127.0.0.1`, `NODE_ENV=production`, `PLACED_DESKTOP=1`, `PLACED_AUTO_SETUP=1`,
   `PLACED_DATA_DIR`, `PLACED_MIGRATIONS_DIR=<serverDir>/drizzle`, `PLACED_PUBLIC_ORIGIN=http://127.0.0.1:3917`,
   `NEXT_TELEMETRY_DISABLED=1`, and `PATH` = the login-shell-less PATH plus `/opt/homebrew/bin`, `/usr/local/bin`,
   `~/.npm-global/bin`, `~/.local/bin` (pure helper `augmentPath(path, home)` with a test). stdout/stderr are appended to
   `<logsDir>/server.log` (rotate: truncate when > 5 MB at startup). `waitForServer(url, timeoutMs)` polls
   `GET http://127.0.0.1:3917/` until any HTTP response, every 250 ms, up to 60 s. `stopServer()` kills the child; the
   app also kills it on `before-quit` and `will-quit`.
   - If port 3917 is already in use before forking (test by binding with `net`), show a native error dialog:
     "Placed can't start: port 3917 is in use (is another copy of Placed, or `npm run dev -- -p 3917`, running?)" and quit.
   - If the server exits before it is healthy, show a dialog with the last 20 log lines and a button to open the log
     file, then quit.
4. `desktop/src/main.ts`:
   - `app.requestSingleInstanceLock()`; second instance focuses the existing window.
   - First-run: if `dataDir` does not contain `placed.db`, show a dialog before starting the server:
     message "Welcome to Placed", detail "Start fresh, or import the data folder from a copy of Placed you ran from the
     repo (it is copied, your original is untouched).", buttons `["Start fresh", "Import existing data…"]`. Import opens
     a directory picker; the chosen folder must contain `placed.db` (else re-prompt with an error); copy it recursively
     (`fs.cpSync`) into `dataDir`. Also honour env `PLACED_IMPORT_FROM=<dir>` (skips the dialog, imports if valid).
   - Then start the server, show one `BrowserWindow` (1280×860, min 900×600, `titleBarStyle: "default"`,
     `webPreferences: { preload, contextIsolation: true, nodeIntegration: false, sandbox: true }`) with a tiny inline
     "Starting Placed…" page (data: URL, matches the app's background colour) until `waitForServer` resolves, then
     `loadURL("http://127.0.0.1:3917/")`.
   - Links: `setWindowOpenHandler` and `will-navigate` send any URL whose origin is not `http://127.0.0.1:3917` to
     `shell.openExternal`, and keep the app window on the app. Downloads (`will-download`) go to the user's Downloads
     folder without a save dialog and show a `Notification` when done.
   - `window-all-closed` → `app.quit()` on every platform (classic Dock app). `activate` with no window → recreate.
   - macOS application menu: app menu (About, Check for Updates… [stub until Task 5, wire later], Open Data Folder,
     Open Logs Folder, Quit), Edit (undo/redo/cut/copy/paste/select all — required for Cmd+V in inputs), View
     (reload, zoom, fullscreen), Window (minimize, close).
   - `desktop/src/preload.ts`: `contextBridge.exposeInMainWorld("placedDesktop", { version, platform, dataDir, getOpenAtLogin, setOpenAtLogin, checkForUpdates, openPath })` over `ipcRenderer.invoke` channels `placed:*`. Implement
     `getOpenAtLogin`/`setOpenAtLogin` with `app.getLoginItemSettings()/setLoginItemSettings({ openAtLogin })` now;
     `checkForUpdates` resolves `{ status: "unavailable" }` until Task 5 replaces it.
5. `desktop/README.md`: how to run in dev (`npm run desktop:dev` from the root once Task 4 exists; for now:
   `npm run desktop:build` + `npm run desktop:start`), where data/logs live, env overrides.
6. Tests: `paths.ts` and `augmentPath` and the "folder contains placed.db" validator are pure; test them with vitest
   (either `desktop/src/lib/*.test.ts` + root vitest include glob, or `tests/desktop/*.test.ts` importing from
   `../../desktop/src/lib/...`). `npm run typecheck` at the root must not pick up `desktop/` (exclude it in root
   `tsconfig.json`), and `cd desktop && npm run build` must pass. Commit (include `desktop/package-lock.json`).

## Task 7 — QA on the real app (run by the controller, not a subagent)

Build the DMG, open the .app from `desktop/out` with `PLACED_USER_DATA_DIR` pointing at a scratch folder, and walk:
first-run dialog → Start fresh → window shows the app → onboarding → Settings shows the "Mac app" section (toggle,
check for updates, data folder) → Autopilot → Setup offers the zip → Feed lists seeded jobs → Cmd+Q stops the server
(port 3917 closed, no orphan process). Then the import path: run again with a fresh scratch folder and
`PLACED_IMPORT_FROM=<previous scratch>/data`, verify the data carried over. Findings go back through fix dispatches.
